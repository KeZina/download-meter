# download-meter

[English](README.md) | Русский

Небольшая CLI-утилита на Node.js и TypeScript для измерения скорости загрузки по URL. Она отправляет HTTP-запросы один за другим, каждый раз дожидается полной загрузки ответа, а затем рассчитывает скорость скачивания.

Для проверки можно использовать **https://picsum.photos/1200/800** — бесплатный API изображений, который без регистрации и API-ключа возвращает случайную фотографию на каждый запрос. Удобный вариант для серии замеров.

## Требования

- Node.js >= 18.17 (используется встроенный `fetch`, отдельный HTTP-клиент не нужен)
- npm

## Установка

```bash
npm install
```

## Запуск

Утилиту можно запускать прямо из TypeScript-исходников через `tsx`. Если не передать аргументы, запросы будут отправляться на адрес по умолчанию (`https://picsum.photos/1200/800`):

```bash
npm run knock
```

Чтобы проверить другой адрес, передайте URL аргументом:

```bash
npm run knock -- https://picsum.photos/1200/800
```

Также можно сначала собрать проект, а затем запустить скомпилированный JavaScript:

```bash
npm run build
node dist/main.js            # URL по умолчанию
node dist/main.js https://picsum.photos/1200/800
```

### Параметры

| Параметр             | По умолчанию                     | Описание                                                                        |
| -------------------- | -------------------------------- | ------------------------------------------------------------------------------- |
| `[url]`              | `https://picsum.photos/1200/800` | Адрес для проверки; поддерживаются только `http` и `https`                      |
| `-c, --count <n>`    | `10`                             | Количество последовательных запросов                                            |
| `-t, --timeout <ms>` | `15000`                          | Тайм-аут каждого запроса в миллисекундах                                        |
| `--max-size <bytes>` | `100000000`                      | Максимальный размер одного ответа в байтах; при превышении загрузка прерывается |
| `-h, --help`         | —                                | Показать справку                                                                |

## Как считаются метрики

Запросы выполняются **строго последовательно**: следующий начинается только после того, как тело предыдущего ответа полностью загружено.

- **Среднее время запроса** — среднее арифметическое времени выполнения всех запросов: от отправки запроса до получения последнего байта ответа. Отображается в миллисекундах, а если значение превышает 1 секунду — в секундах.
- **Общий объём загруженных данных** — сумма байтов, фактически полученных в телах всех успешных ответов. Данные подсчитываются по мере чтения потока, а не по заголовку `Content-Length`.
- **Скорость загрузки** — `общий объём загруженных байтов / суммарное время загрузки`. Дополнительно выводится скорость с учётом накладных расходов каждого запроса: установки соединения, TLS-рукопожатия и сетевой задержки.

### Единицы измерения

Во всех расчётах и примерах используются десятичные единицы (SI):

- `1 KB = 1 000 байт`
- `1 MB = 1 000 KB`
- `1 GB = 1 000 MB`

Скорость выводится в `B/s`, `KB/s`, `MB/s` и т. д. Например, `1 KB/s = 1 000 байт/с`. Это соответствует принятому способу обозначения пропускной способности сети и скорости скачивания в большинстве браузеров.

## Обработка ошибок

При ошибке утилита сразу прекращает работу, выводит сообщение через `silly-logger` и завершает процесс с кодом `1`. Это происходит, если:

- передан некорректный абсолютный URL;
- используется протокол, отличный от `http:` или `https:` (например, `file://` или `ftp://`);
- сервер вернул HTTP-статус вне диапазона **2xx** (например, 404 или 500);
- в процессе чтения ответа превышен лимит **`--max-size`** — защита от слишком больших ответов, в том числе декомпрессионных бомб;
- истёк тайм-аут запроса (`--timeout`);
- возникла сетевая ошибка: не удалось разрешить DNS-имя, сервер отказал в соединении, соединение было сброшено и т. п.

## Тестирование

Тесты написаны на встроенном в Node.js тест-раннере (`node:test`), без дополнительных фреймворков. Для HTTP-запросов используется локальный сервер на loopback-интерфейсе.

```bash
npm test
```

Проверяются форматирование единиц измерения, валидация URL (`parseUrl`), выполнение одного запроса (`knock`) — успешный ответ, статус вне 2xx, превышение размера ответа, зависший ответ и ошибка соединения — а также агрегация результатов нескольких запросов в `meterUrl`.
